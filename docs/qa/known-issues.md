# Known issues and accepted risks

Every line here is something the audits found (or could not check) that was left as it is, with the reason. When one is fixed, delete the line. When a new audit finding is accepted instead of fixed, add it here with a reason.

## Accepted, with a reason

| # | Where | What | Why it is accepted |
|---|---|---|---|
| 1 | All pages, Lighthouse SEO | "Page is blocked from indexing" (SEO scores 63 instead of 100). | Staging is `noindex,nofollow` on purpose (`"staging": true` in `tools/seo.json`). Everything else in the SEO category passes. Re-run Lighthouse after launch with staging off. |
| 2 | Lighthouse, all pages | "Minify CSS" and "Minify JavaScript" (about 3 KB each after compression). | The prototype ships readable source files with no build step. Laravel's Vite build minifies and fingerprints them. |
| 3 | Lighthouse, all pages | "Use efficient cache lifetimes". | Cache headers are set by the web server, not by the page. GitHub Pages and most hosts cache for 10 minutes by default; the cache-busting `?v=` hashes already change when a file changes, so the server can be told to cache for a year. Configure this in the production server. |
| 4 | Lighthouse, all pages | "Render-blocking requests" (the stylesheets, about 250 ms on a simulated slow phone). | The CSS is split in six small files on purpose (shared tokens, base, components, layout, one per page). A bundler would merge them. Over HTTP/2 the cost is one round trip. |
| 5 | Lighthouse, checkout | "Reduce unused CSS" (about 10 KB). | The shared component file serves every page. Splitting it by page needs a build step; the gzip cost is small (the largest page loads 23 KB of CSS, budget 70 KB). |

| 7 | `html-validate` | `prefer-native-element` is relaxed for `role="list"` on an `<ol>` (table of contents) and `role="region"` on the verify-email banner. | Same VoiceOver reason for the list. The banner is a hidden `<div>` that the page script shows; it is not worth restructuring. |

| 11 | Windows WebKit (Playwright) | Text looks thinner than in Chromium and Firefox. | The font files are loaded and the weight axis works (measured widths change with weight); it is the anti-aliasing of Playwright's Windows WebKit build. iOS Safari renders text differently. | 12 | Keyboard audit | "No large upward jumps in the order": the fixed bottom tab bar and the sticky buy bar come last in the page order but sit at the bottom of the screen; on the desktop checkout the order summary comes after the form but sits at the right. | The order follows the document (form, then summary, then footer, then the fixed bars), which is the logical reading order. | 13 | Cart drawer | The quantity box has `name="qty[]"`. | A repeated row in a list: the server decides the real field names when the drawer is built from the database. |
| 14 | Forced colours (Windows High Contrast) | Icon-only buttons (close, password toggle) and the small gallery dots have no border of their own. | Their icons and dots are drawn in the system text colour and stay visible. Screenshots are in the QA run output; confirm on a real Windows machine with a contrast theme if this audience matters. |
| 15 | Hover-only styling | The product-card lift and the centred "Quick add" pill appear on hover for mouse users only. | On touch the round "+" quick-add button is always visible and the card needs no hover. The audit confirmed nothing is available only by hover. |
| 16 | Lighthouse, mobile, home page | Total Blocking Time about 216 to 219 ms against a target of 200 ms (every other page is under 120 ms). | The remaining time is the browser's first layout of the long home page on a simulated 4x slower phone, not script work. Revisit when real photos exist. |
| 17 | Hygiene audit, unused CSS | 44 selectors match nothing on any audited page or state. | They are base defaults (h4 to h6, img, hr), focus and hover states the check cannot trigger, and variants kept on purpose (for example the sale-only and refunded badges that appear only after an interaction, the sky announcement bar, error badge). 14 rules were provably dead (named nowhere in pages, scripts or tools) and were deleted. |

| 19 | Header, favicon | `<link rel="icon" href="data:,">` (an empty icon). | There is no logo yet. It stops every first visit asking for `/favicon.ico` (a 404 that Lighthouse reports as a console error). Replace with the real icon (open decision 28). |

## Could not be verified here

- **A real iPhone and a real Android phone.** Playwright's WebKit and Chromium are close but not the same as iOS Safari and Chrome on Android: pinch zoom, the on-screen keyboard resizing the page, safe-area insets, rubber-band scrolling, "add to home screen" and OS dark mode forcing cannot be confirmed from a desktop. Use `real-device-checklist.md`.
- **Screen readers.** axe and the static checks catch missing names and roles; they cannot tell whether the page *reads* well in VoiceOver, TalkBack or NVDA. A short manual pass with each (home, product, cart, checkout, track) is recommended before launch.
- **Real network.** Lighthouse uses a simulated slow 4G and 4x CPU slowdown on a laptop. Real phones and real hosting will differ; the budgets in `check-budget.mjs` keep the page weight from growing.
- **Print.** The return and policy pages have print styles that were looked at once; they are not part of the automated audits.
- **Email.** No email is sent by the prototype; none of the order or verification emails can be tested until the backend exists.
- **Production hosting headers** (gzip or Brotli, cache lifetimes, security headers). The local test server mimics GitHub Pages for gzip and a 10 minute cache only.
